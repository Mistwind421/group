# DjangoBlog 模板继承机制分析
## 一、模板总体结构说明
DjangoBlog 的前端模板存放在 `templates` 目录下，采用 Django 的模板继承 `{% extends %}`、组件包含 `{% include %}`、自定义模板标签 `{% load %}` 机制实现页面复用，减少HTML代码冗余。

## 二、顶层母模板
文件路径：`templates/share_layout/base.html`
1. 该模板是整个博客系统的**最顶层母模板**，不继承任何其他html模板。
2. 模板内部使用 `{% load blog_tags %}`，加载 `templatetags/blog_tags.py` 自定义标签与过滤器，用于渲染后端传来的数据。
3. 使用 `{% include %}` 引入公共碎片组件：`nav.html`（导航栏）、`footer.html`（页脚）等通用UI片段。
4. 定义多个 `{% block %}` 代码块，供子模板重写填充各自页面的特有内容。

## 三、继承母模板的子页面
子模板第一行均使用语法 `{% extends 'share_layout/base.html' %}` 实现模板继承，重写base.html中定义的block块：
1. `templates/blog/article_index.html`：文章列表首页
2. `templates/blog/article_detail.html`：文章详情页面
3. `templates/blog/category.html`：分类列表页面
4. `templates/blog/tag.html`：标签列表页面

> 子模板不需要重复写头部、导航、页脚等公共代码，只需要填充页面独有的业务内容块。

## 四、被include引入的碎片组件
碎片组件只负责局部UI，不独立作为完整页面访问，由母模板引入复用：
- `nav.html`：网站顶部导航栏
- `footer.html`：网站底部页脚信息

## 五、自定义模板标签依赖
- 文件位置：`blog/templatetags/blog_tags.py`
- 模板中通过 `{% load blog_tags %}` 导入，提供自定义函数、过滤器；
- base.html以及各个子页面都可以调用里面的方法，完成文章数量统计、分类渲染等逻辑。

## 六、继承与复用总结
1. **继承（extends）**：`article_index.html`、`article_detail.html`、`category.html`、`tag.html` 全部继承 `base.html`，实现页面骨架复用。
2. **包含（include）**：`base.html` include导航、页脚碎片，拆分公共局部组件。
3. **自定义标签（load）**：模板依赖blog_tags.py，把部分展示逻辑放到py文件，模板只负责渲染展示。
