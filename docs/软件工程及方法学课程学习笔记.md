# 软件工程及方法学 课程学习笔记

（结合 DjangoBlog 开源项目实践作业整理）

## 一、软件工程基本概念

### 1. 什么是软件工程
软件工程是应用计算机科学理论和技术以及工程管理原则和方法，按预算和进度开发满足用户需求的软件产品的活动。核心目标是提高软件质量、控制开发成本、保证按期交付。

### 2. 软件工程三要素
- 过程：开发软件的一系列活动（需求分析、设计、编码、测试、维护）
- 方法：完成各项任务的技术手段（结构化方法、面向对象方法）
- 工具：辅助开发和管理的软件环境（IDE、Git、测试工具等）

### 3. 软件危机
早期软件开发凭个人经验，导致：进度失控、成本超支、质量低劣、维护困难。软件工程就是为了解决软件危机而诞生。

## 二、软件生命周期（SDLC）

软件从提出、实现、使用维护到停止使用的全过程。

| 阶段 | 主要任务 | 产物 |
| ---- | ---- | ---- |
| 可行性研究 | 技术/经济/法律可行性分析 | 可行性报告 |
| 需求分析 | 明确系统要做什么 | 需求规格说明书 |
| 概要设计 | 系统总体结构、模块划分 | 概要设计文档 |
| 详细设计 | 每个模块的实现细节 | 详细设计文档 |
| 编码 | 编写程序代码 | 源代码 |
| 测试 | 发现并修正错误 | 测试报告 |
| 维护 | 修改、完善、升级 | 维护记录 |

### 常见开发模型
- 瀑布模型：阶段顺序执行，适合需求明确的项目
- 螺旋模型：结合原型和瀑布，注重风险分析
- 敏捷开发：迭代增量，快速响应需求变化（本次小组作业即采用 Git 分支协作模式）

## 三、软件工程方法论

### 1. 结构化方法
- 自顶向下、逐步求精
- 数据流图（DFD）、结构图描述系统

### 2. 面向对象方法
- 三大特性：封装、继承、多态
- 统一建模语言 UML：用例图、类图、时序图、活动图、包图等
- 本次 DjangoBlog 项目即采用面向对象思想：Django 将数据、业务逻辑、展示分离

### 3. Django 的 MTV 架构（对应传统 MVC）
| 概念 | Django 对应 | 职责 |
| ---- | ---- | ---- |
| Model（数据） | models.py | 定义数据表结构 |
| Template（视图） | templates/ | 页面展示模板 |
| View（控制） | views.py | 业务逻辑处理 |
| URL 路由 | urls.py | 地址与视图的映射 |

## 四、本项目实践：DjangoBlog 博客系统

### 1. 项目简介
- 技术栈：Django + MySQL
- 来源：GitHub 开源项目
- 作业主题：学习笔记博客

### 2. 团队分工（分支协作模式）
- master：最终成品主分支，禁止直接修改
- develop：小组整合的开发总分支
- feature/xxx-week4：个人工作分支（如 feature/zhangsan-week4）
- 我的任务 B：页面截图采集 + 页面流转思维导图

### 3. 团队协作流程（Git 版本控制）
```
git clone <仓库地址>          # 克隆远程仓库
git checkout develop          # 切到开发总分支
git pull origin develop       # 拉取小组最新代码
git checkout -b feature/xxx-week4  # 创建个人分支
# 在个人分支上完成任务
git add .                     # 加入暂存区
git commit -m "任务说明"       # 提交
git push origin feature/xxx-week4  # 推送到远程
# 在 GitHub 上发起 Pull Request 合并到 develop
```
要点：
- 不在 master 直接改代码
- 每次开工先 pull 同步最新代码，减少冲突
- 分支命名用英文，如 feature/zhangsan-week4

### 4. 我的任务（B任务）：页面与流转
- 启动 Django 项目，浏览器访问 127.0.0.1:8000
- 采集页面截图：首页、文章详情页、登录页、注册页、后台管理页
- 绘制页面流转思维导图：梳理页面之间如何跳转
- 交付物统一放在 docs 文件夹

## 五、软件测试基础

### 测试层次
1. 单元测试：测试单个函数/模块
2. 集成测试：测试模块之间接口
3. 系统测试：测试整个系统功能
4. 验收测试：确认满足用户需求

### 测试方法
- 黑盒测试：不看内部代码，验证输入输出是否符合预期
- 白盒测试：基于内部逻辑结构设计测试用例

## 六、本项目中学到的要点

1. Git 分支协作是敏捷开发的落地实践，个人任务隔离能有效避免代码冲突
2. Django MTV 架构实现关注点分离，符合软件工程高内聚、低耦合原则
3. 需求分析阶段要把"博客主题（学习笔记）"、页面清单（首页、详情、登录、注册、后台）先定义清楚，后续开发才不返工
4. 文档与代码同样重要，交付物要规范归档（本次统一放入 docs 目录）

## 七、课程小结

软件工程的核心不是单纯写代码，而是：
- 用规范的过程管理复杂度
- 用文档和版本控制保证可维护
- 用测试保证质量
- 用团队协作方法保证进度

本次 DjangoBlog 实践作业让我们完整走了一遍"需求分析→设计→编码→测试→文档交付"的软件工程流程，并通过 Git 分支实现团队协作。
